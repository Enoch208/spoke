## External research provenance

The captured Nansen example uses public address `0xd8da6bf26964af9d7eed9e03e53415d37aa96045`. It is explicitly **not a participating Spoke distributor**. Three supported endpoints were queried with the provider's free-plan allowance. A diagnostic retry of the transactions endpoint used one additional included credit; no credits were purchased. Budget reservations remain durable.

The transactions result samples 100 records in the requested 30-day window across seven networks. `truncated: true` and a null total avoid treating this as complete wallet history. The first funding observation and Monad relationship retain source transaction hashes and independent timestamps. Labels are provider context, not identity verification or a trust score.

The provider returned naive UTC timestamps on its transactions endpoint. One was matched to the canonical Base block timestamp before normalization was added. The original captured response was then reprocessed into the cache without another provider call. The evidence file contains normalized public evidence, not an API key or account record.

The updated application passes 717 tests across 76 files with disposable PostgreSQL and both required Anvil chains, without skipped suites. Typecheck, lint, formatting and the production web build pass. SDK 0.1.3 passes clean packed installation, ESM/CommonJS loading and consumer typechecks; npm publication is a separate authenticated release step. Check [CI](https://github.com/Enoch208/spoke/actions/workflows/ci.yml) for the latest pushed revision.

Public browser checks cover Passport receipts, network navigation, activity, indexer freshness and narrow layouts. Tests with an injected PRF prove encryption and serialization behavior; they do not prove a real hardware or synced passkey will work across devices. No simulated identity ceremony is presented as a physical-device test.

## Human verification procedure

1. On a supported HTTPS browser, create a new test account with a passkey and record browser, OS and provider. Preserve a campaign/referral return URL. Cancel once, then complete the ceremony and verify the restored page.
2. Perform one testnet link or purchase action with the account. Record its transaction and indexed receipt; verify pending → confirmed → indexed states and bounded gas assistance where eligible.
3. Open a campaign notebook, write a non-sensitive test note, **Encrypt & sync**, then export an encrypted backup. Confirm the server payload contains an envelope, no plaintext. Reload and unlock with the original passkey.
4. On a second device where the provider supplies that same passkey with PRF support, sign in and unlock the synced ciphertext. If the credential is unavailable or PRF unsupported, record that limitation instead of claiming success. Test conflicting copies and backup restoration on disposable test text.
5. Ask a merchant tester to compare two consenting distributors, inspect their receipts, invite one, and complete invitation acceptance and link creation. Record confusion, completion time and failures without inventing adoption metrics.

The next highest-impact work is this physical-device verification and observed merchant/distributor testing. Mainnet commerce additionally requires independent security review, capacity work and explicit release approval. Current limits remain 128 campaigns, 256 nodes and 100 sales per campaign; settlement has not been independently audited.
